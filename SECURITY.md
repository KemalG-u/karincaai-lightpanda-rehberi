# Security Policy

## Supported versions

| Version | Supported |
|---|---|
| latest commit on `main` | yes |
| older | no |

## Reporting a vulnerability

Please do **not** open a public issue for a security problem.

Report it privately with GitHub's private vulnerability reporting: open the repository's **Security** tab and choose **Report a vulnerability** (https://github.com/KemalG-u/karincaai-lightpanda-rehberi/security/advisories/new).

Include: affected version, a description, steps to reproduce, and the impact you see. Never include real secrets or personal data in a report; describe where they appear instead.

## What to expect

This is a one-person project maintained on a best-effort basis. The maintainer aims to send an initial response within 14 days of a report. A fix date is not promised; the maintainer will tell you what is planned.

## Scope

This is a static guide (HTML, images, benchmark data) published through GitHub Pages. In scope: script injection or unsafe content in `index.html`, and secrets or personal data accidentally present in the files. Factual or measurement errors can be reported as ordinary issues.
